# Tags

Registry for greppable `[[type:slug]]` anchors in the TVC RootEncoder fork (see the TVC
[Code Tagging System](https://github.com/masoumehizadi/TVC-Wiki/wiki/Code-Tagging-System)).
Earlier fork additions are marked with the single-bracket `[tvc-sei-capture-ts]` form at the
call sites; they are registered by the app's `[[contract:encoder-stats]]` row in
`mobile_streaming/docs/TAGS.md`.

| Tag | Location | Purpose |
|-----|----------|---------|
| `[[contract:change-video-size-on-fly]]` | `library/src/main/java/com/pedro/library/base/StreamBase.kt` (`changeVideoSizeOnFly`, `resetStreamVideoEncoder`, `configuredWidth/Height`, `prepareEncoders`), `library/src/main/java/com/pedro/library/view/GlStreamInterface.kt` (`removeMediaCodecSurface(w, h)`), `encoder/src/main/java/com/pedro/encoder/video/VideoEncoder.java` (`reset(width, height)`, `prepareVideoEncoder(width, height)`), `common/src/main/java/com/pedro/common/frame/VideoInfo.kt`, `common/src/main/java/com/pedro/common/frame/MediaFrame.kt` (`videoInfo`), `common/src/main/java/com/pedro/common/base/BaseSender.kt` (`videoInfo`, `sendMediaFrame`), `srt/src/main/java/com/pedro/srt/mpeg2ts/packets/H26XPacket.kt` (`load`, `sendVideoInfo(VideoInfo)`), `srt/.../SrtSender.kt` + `udp/.../UdpSender.kt` (`setVideoInfo`); tests `srt/src/test/java/com/pedro/srt/mpeg2ts/H26XPacketTest.kt`, `srt/src/test/java/com/pedro/srt/srt/SrtSenderTest.kt`; consumer: Android app adaptive-resolution rung (tvc root repo, docs/ADAPTIVE-RESOLUTION-PLAN.md) | Change the ENCODED size under a live SRT/UDP socket. `prepareVideo` refuses while streaming and MediaCodec cannot resize in place, so the rung is a stop/configure/start of the stream encoder — the same path `resetVideoEncoder` takes for codec errors — with the size written into the encoder's stored fields first; the socket, sender queue and TS muxer never see it and the PTS base survives. Parameter sets are bound PER FRAME: the sender stamps the SPS/PPS generation in force onto each video `MediaFrame` at enqueue time and `H26XPacket` muxes a keyframe with its own, so a keyframe of the old size still queued when the new codec's `formatChanged` lands (a rung-down fires under congestion, i.e. with a backlog) keeps the sets it was encoded against — the sets travel in queue order, never out of band. The GL render-target resize is queued on the render thread together with the old surface's detach, so no frame is drawn with one size's viewport into the other's surface. The size given to `prepareVideo` is kept apart from the live encode size (`videoEncoder.width/height` = the current rung): `changeVideoSource` initialises the new source at the configured size and `prepareEncoders` (stream/record end) re-prepares at it, so a rung never leaks into the next session or the camera. Refused while a record SHARES the encoder: the MP4 track keeps its original SPS and would stop decoding at the switch. If the old size cannot be restored after a refused rung the loss is reported through `CodecErrorCallback` (VIDEO_CODEC) rather than hidden behind `false`. SRT and UDP only: RTMP/RTSP/WHIP replace their whole packetizer object in `setVideoInfo` (no shared per-frame seam) and signal parameter sets out of band (RTMP connect metadata, SDP `sprop-parameter-sets`), so a mid-stream size change is not supported there. Published as JitPack tag `2.8.0-tvcsrt5` (`2.8.0-tvcsrt4` = first cut, sets applied out of band). |
| `[[gotcha:gl-draw-time-pts]]` | `encoder/src/main/java/com/pedro/encoder/input/gl/FrameTimestampMapper.kt` (`map`, `reset`), `library/src/main/java/com/pedro/library/view/GlStreamInterface.kt` + `OpenGlView.kt` (`draw`, `start`); test `encoder/src/test/java/com/pedro/encoder/input/gl/FrameTimestampMapperTest.kt` | The encoder surface PTS must come from the source frame (SurfaceTexture timestamp = camera sensor time), mapped onto the audio clock (elapsedRealtimeNanos) by an offset frozen after 30 frames. Stamping the GL draw time jitters frame spacing by ms; MediaMTX then reports "part duration changed ... iOS clients" and iPhone LL-HLS players drop. No timestamp / repeated frame / jump falls back to the steady clock. `2.8.0-tvcsrt8`. |
| `[[gotcha:cfr-pts-grid]]` | `encoder/src/main/java/com/pedro/encoder/input/gl/FrameTimestampMapper.kt` (`setFrameRate`, `map`); Camera2/Camera1 AE fps range selection; test `LlHlsPartSimTest` | Even honest camera timestamps vary (AE lowers fps, sensor jitter), so LL-HLS 200 ms parts flip 7↔8 frames and iOS players drop. Each mapped time snaps to the nearest free slot of a 1/fps grid (−0.5 … +0.9 frame of capture time, mean 0; drops skip slots; >bound re-anchors; drift ≤20 µs/frame); camera AE range fixed [N,N] when listed. `2.8.0-tvcsrt9`. |
